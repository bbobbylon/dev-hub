Dissecting one real API call

A request goes out, a response comes back — that's the whole protocol. Every callout on the left panel has a matching note; read them in number order.

The request — what you send
POST /v1/orders HTTP/1.11 · METHOD + PATH
Host: api.shop.dev
Authorization: Bearer eyJhbGci…2 · WHO YOU ARE
Content-Type: application/json3 · BODY FORMAT
 
{ "item": "coffee-beans", "qty": 2 }4 · PAYLOAD
The response — what comes back
HTTP/1.1201 Created5 · STATUS
Location: /v1/orders/81276 · WHERE IT LIVES
 
{ "id": 8127, "status": "pending" }
1
Verb + noun. POST = "create", the path names what. GET reads, PUT replaces, DELETE removes.
2
The token is your ID card. No token, no order — the server has no session memory (HTTP is stateless).
3
A promise about the body. "What follows is JSON." Wrong label → 415 Unsupported Media Type.
4
The actual data. GETs usually have no body; POST/PUT carry one.
5
Three digits, one story. 2xx worked · 4xx you goofed · 5xx server goofed. 201 = "created something new."
6
Your receipt. The new order's permanent address — GET it any time.
