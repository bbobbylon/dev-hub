CLI Basics

The command line is just a conversation: the shell prints a prompt, you type a command, it runs and prints the result, then prompts again. Master a dozen commands — move around, look at files, create and delete things, and ask for help — and you can drive any machine. This page shows them in Bash, PowerShell, and CMD together.

What is the command line — and why does every developer eventually need to know at least 12 commands that work on any machine?

The idea

What is the CLI, really?

The command-line interface (CLI) is a text-based way to interact with an operating system and its programs. Instead of clicking icons in a GUI, you type commands that the shell interprets and executes. The shell is the program that accepts your commands, figures out which program to run, runs it, and shows you the output. On Linux/macOS the default shell is usually Bash or Zsh. On Windows, PowerShell is the modern shell, with CMD (cmd.exe) being the legacy option.

Motivation

Why learn the CLI at all?

01
Many tools are CLI-only
Most CI/CD pipelines, Docker, Kubernetes, cloud CLIs (az, aws, gcloud), and deployment scripts are CLI-based.
02
Automation
If you can do something in the CLI, you can script it. Click-based UIs can't be scripted.
03
Remote access
When you SSH into a server, there's no GUI — you only have a CLI.
04
Speed
Experienced developers navigate and manipulate files faster in the CLI than in any file browser.

Every command answers with one

Exit codes

Every command exits with a numeric code. In scripts and CI/CD, exit codes chain commands — command1 && command2 runs command2 ONLY if command1 succeeded. CI/CD pipelines fail the build if any command exits non-zero.

0 = success vs. anything else = error
There are no dumb questions
"Do I need to memorize every flag?"
No. Muscle memory comes from repetition, not memorization. Run the commands in the walkthrough below a few times and the common ones will stick — keep man or --help open for the rest.
Cheat sheet — Bash, PowerShell, and general pipes/exit codes side by side
Navigation + file ops · Bash
Copied!
pwd # print working directory
ls -la # -l=long, -a=all (hidden too)
cd /var/log # absolute path
cd .. # up one level
cd ~/projects # ~ = home directory
# create / delete:
mkdir -p a/b/c # -p = parents, no error if exists
rm -rf ./build # DANGER: no undo!
touch file.txt # create / touch a file
cp -r src/ dest/ # -r = recursive
mv old.txt new.txt # rename / move
# view contents:
cat file.txt # whole file
less file.txt # page through (q to quit)
head -20 file.txt # first 20 lines
Navigation + file ops · PowerShell
Copied!
Get-Location # = pwd
Get-ChildItem -la # = ls -la
Set-Location path # = cd
# create / delete:
New-Item -ItemType Directory -Force a/b/c # mkdir -p
Remove-Item -Recurse -Force ./build # rm -rf
New-Item -ItemType File file.txt # touch
Copy-Item -Recurse src/ dest/ # cp -r
Move-Item old.txt new.txt # mv
# view contents:
Get-Content file.txt # cat
Get-Content file.txt -Head 20 # head -20
Get-Content app.log -Wait # tail -f
(Get-Content file.txt).Count # wc -l
# find / search:
Get-ChildItem -Recurse -Filter "*.java" # find
Select-String "spring" app.log # grep
Pipes, redirection, exit codes
Copied!
# pipes: one command's output → next's input
ls -l | grep ".java" # only .java files
cat app.log | grep ERROR | head -10 # first 10 errors
ps aux | grep "spring" | wc -l # count matches
# redirection:
echo "hello" > file.txt # overwrite
echo "world" >> file.txt # append
mvn test 2>errors.txt # stderr to file
mvn test >out.txt 2>&1 # both streams
# exit codes (critical for CI/CD):
ls /var/log; echo "exit: $?" # $? in Bash
$LASTEXITCODE # in PowerShell
mvn clean install && docker build . # docker only if mvn succeeded
