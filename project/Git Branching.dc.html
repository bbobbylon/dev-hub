A feature branch, start to merge

The same repository at four moments. Follow the dots left to right — every dot is a commit, every label is the command that created that moment.

1
One line of history
Three commits on main. The branch name is just a sticky note on the newest commit.
2
Branching is free
git switch -c feat/login adds a second sticky note to the same commit. Nothing is copied.
3
The lines diverge
You commit twice on the branch (sage). Meanwhile a teammate lands a commit on main (terracotta). Neither disturbs the other.
4
Merge ties the knot
git merge feat/login creates one commit with two parents. Both histories survive. A conflict only happens if both lines touched the same lines of the same file.
There are no dumb questions
"If branching is so cheap, why do teams fear merges?"
Because fear grows with divergence. Two lines that drift apart for weeks touch the same files; two lines merged daily barely overlap. The cure isn't avoiding branches — it's merging often.
